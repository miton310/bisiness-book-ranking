# PA-API統合 - 要求定義

## 概要

書籍情報の取得方法を大幅に改善する。従来のパターンマッチングによる書籍タイトル抽出を廃止し、Amazon PA-API（Product Advertising API）を使用してAmazonリンクから直接書籍情報を取得する。

## 背景・課題

### 従来の問題点

1. **パターンマッチングの限界**: チャンネルごとに異なる概要欄フォーマットに対応するため、複雑な正規表現パターンが必要だった
2. **非書籍商品の混入**: amzn.toリンクから抽出した商品が書籍とは限らない（日用品、食品、電子機器など）
3. **メンテナンス負担**: NGワードリストが肥大化（300+件）し、管理が困難
4. **データ品質**: タイトルのクリーニング処理が不完全で、ゴミデータが混入

### PA-API導入のメリット

1. **正確な書籍判定**: Binding（製本形態）で書籍かどうかを確実に判定
2. **高品質なデータ**: タイトル、著者、出版社、画像URLなどを正確に取得
3. **シンプルな実装**: パターンマッチング不要、Amazonリンクがあれば情報取得可能
4. **将来の拡張性**: ISBNなしの書籍、洋書、新刊にも対応可能

## 要求事項

### 機能要件

1. 概要欄からAmazonリンク（amzn.to, amazon.co.jp/dp/）を抽出
2. PA-APIで商品情報を取得
3. Bindingで書籍かどうかを判定（書籍以外は除外）
4. 書籍情報（タイトル、著者、出版社、画像URL、ASIN）を取得

### 非機能要件

1. PA-APIのレート制限（1リクエスト/秒）を遵守
2. amzn.to短縮URLのリダイレクト解決に対応
3. エラー時のリトライ処理（Exponential backoff）

## 受け入れ条件

- [ ] Amazonリンクから書籍情報が正確に取得できる
- [ ] 書籍以外の商品（CD、DVD、雑貨など）が除外される
- [ ] 1チャンネルずつ処理できる（--channel オプション）
- [ ] 既存データとマージできる（差分更新対応）

## 制約事項

- PA-APIの認証情報（AMAZON_ACCESS_KEY, AMAZON_SECRET_KEY）が必要
- 処理時間が長い（1チャンネルあたり数分〜数十分）
- PA-APIのクォータ制限あり
